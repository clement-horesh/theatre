Theatre / Architecture / Source-derived

Your library. Two playback engines. One native app.

Theatre runs on your Mac. Your Jellyfin server owns the catalog and watch history; Theatre coordinates browsing, playback, and an account-scoped offline library.

Playback chooses a source, then an engine

PlaybackSession prefers a completed local download when available, otherwise asks Jellyfin for a stream. PlaybackController uses VLC for broad format support and AVPlayer for native presentation. Apple playback may require a compatible server stream.

Offline state stays on your Mac

Original files, subtitles, artwork, metadata, and pending progress live under ~/Library/Application Support/Theatre/Downloads, separated by server and account. Progress sync preserves newer server viewing activity. Keychain stores the issued token; passwords are never saved.

Scope and source evidence
  • App ownership and sign-in: Sources/JellyMac/AppModel.swift and JellyMacApp.swift.
  • Playback coordination and reporting: PlaybackSession.swift, PlaybackReporter.swift, PlaybackController.swift, and ApplePlaybackController.swift.
  • Server requests and reusable models: Sources/JellyfinKit/.
  • Local persistence: DownloadManager.swift, DownloadFileIO.swift, and SessionStore.swift.
  • Overview grouping: individual views, artwork caching, player windows, media keys, and other native adapters are included within their parent components. Arrows show the principal interactions, not every ownership reference; local file URLs reach the playback engine via the session.
  • Outside this runtime view: Sparkle updates and GitHub release distribution, external trailer embeds, and the companion Next.js website maintained separately from this app repository.
